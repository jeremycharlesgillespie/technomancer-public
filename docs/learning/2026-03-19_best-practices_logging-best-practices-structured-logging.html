Logging Best Practices: Structured Logging

Quick Overview

Structured logging is the practice of writing log messages in a consistent, machine-readable format instead of free-form text strings. Rather than logging "User john@example.com failed to login at 2024-01-15", you'd log structured data with clear key-value pairs like {"timestamp": "2024-01-15T10:30:00Z", "event": "login_failed", "user_email": "john@example.com", "ip_address": "192.168.1.100"}.

This approach transforms your logs from human-readable stories into queryable data. When every log entry follows a predictable structure, you can easily search, filter, aggregate, and analyze your application's behavior. Think of it as the difference between keeping notes in a diary versus storing information in a database – both contain the same information, but one is dramatically more useful for finding patterns and answering specific questions.

// Traditional logging (hard to parse)
console.log(User ${email} attempted login from ${ip} and failed due to invalid password);


// Structured logging (machine-readable)

logger.info('login_attempt', {

  user_email: email,

  ip_address: ip,

  success: false,

  failure_reason: 'invalid_password',

  timestamp: new Date().toISOString()

});

Modern applications generate thousands of log entries per minute. Without structure, finding specific events or understanding system behavior becomes like searching for a needle in a haystack. Structured logging turns that haystack into an organized warehouse where you can quickly locate exactly what you need.

How This Makes You a Better Developer

Mastering structured logging significantly elevates your debugging and system monitoring skills, making you more valuable in any development team. When production issues arise (and they always do), developers who understand structured logging can diagnose problems in minutes rather than hours. You'll be able to quickly correlate events across different services, track user journeys through complex workflows, and identify performance bottlenecks with surgical precision.

This skill becomes even more critical as you work with microservices architectures, distributed systems, or any application that scales beyond a single server. Engineering managers and senior developers recognize that good logging practices are often what separates junior developers from those ready for senior roles. Companies increasingly rely on observability and monitoring to maintain system reliability, and structured logging is the foundation of effective observability. Understanding these concepts positions you for roles in DevOps, site reliability engineering, and senior backend development where system monitoring expertise is essential.

How to Implement It

Let's walk through implementing structured logging step by step, starting with choosing the right tools and establishing consistent patterns.

Step 1: Choose Your Logging Library

For JavaScript/Node.js applications, popular structured logging libraries include Winston, Pino, and Bunyan. Here's a basic setup with Winston:

const winston = require('winston');


const logger = winston.createLogger({

  level: 'info',

  format: winston.format.combine(

    winston.format.timestamp(),

    winston.format.errors({ stack: true }),

    winston.format.json()

  ),

  transports: [

    new winston.transports.File({ filename: 'error.log', level: 'error' }),

    new winston.transports.File({ filename: 'combined.log' }),

    new winston.transports.Console({

      format: winston.format.simple()

    })

  ]

});



module.exports = logger;

Step 2: Define Your Log Schema

Establish consistent field names across your application. Create a logging utility that enforces this structure:

class StructuredLogger {
  constructor(service_name, version) {
    this.service_name = service_name;
    this.version = version;
  }


createLogEntry(level, event_name, data = {}) {

    return {

      timestamp: new Date().toISOString(),

      level: level,

      service_name: this.service_name,

      service_version: this.version,

      event_name: event_name,

      ...data

    };

  }



info(event_name, data) {

    const logEntry = this.createLogEntry('info', event_name, data);

    logger.info(logEntry);

  }



error(event_name, error, data = {}) {

    const logEntry = this.createLogEntry('error', event_name, {

      error_message: error.message,

      error_stack: error.stack,

      ...data

    });

    logger.error(logEntry);

  }



warn(event_name, data) {

    const logEntry = this.createLogEntry('warn', event_name, data);

    logger.warn(logEntry);

  }

}



// Usage

const appLogger = new StructuredLogger('user-service', '1.2.3');



// In your application code

appLogger.info('user_created', {

  user_id: user.id,

  user_email: user.email,

  registration_source: 'web_form'

});



appLogger.error('database_connection_failed', error, {

  database_host: config.db.host,

  retry_attempt: 3

});

Step 3: Add Context and Correlation

For web applications, add middleware to inject request context:

const express = require('express');
const { v4: uuidv4 } = require('uuid');


function loggingMiddleware(req, res, next) {

  req.correlation_id = uuidv4();

  req.logger = {

    info: (event, data) => appLogger.info(event, {

      correlation_id: req.correlation_id,

      request_method: req.method,

      request_url: req.url,

      user_id: req.user?.id,

      ...data

    }),

    error: (event, error, data) => appLogger.error(event, error, {

      correlation_id: req.correlation_id,

      request_method: req.method,

      request_url: req.url,

      user_id: req.user?.id,

      ...data

    })

  };

  next();

}



app.use(loggingMiddleware);



// In your route handlers

app.post('/api/orders', (req, res) => {

  try {

    const order = createOrder(req.body);

    req.logger.info('order_created', {

      order_id: order.id,

      order_total: order.total,

      items_count: order.items.length

    });

    res.json(order);

  } catch (error) {

    req.logger.error('order_creation_failed', error, {

      request_body: req.body

    });

    res.status(500).json({ error: 'Failed to create order' });

  }

});

Step 4: Implement Log Levels Consistently

Use log levels strategically:


  • ERROR: System errors, exceptions, failed operations

  • WARN: Recoverable issues, deprecated usage, performance concerns

  • INFO: Important business events, successful operations

  • DEBUG: Detailed execution flow (disabled in production)


Where to Use / Where NOT to Use

Good use cases:


  • Production applications with monitoring requirements: When you need to track system health, user behavior, or business metrics in production environments.

  • Microservices architectures: Where you need to trace requests across multiple services and correlate logs from different components.

  • High-traffic applications: When you generate enough log volume that manual inspection becomes impractical and you need automated analysis.


Avoid when:

  • Simple scripts or one-off utilities: The overhead isn't justified for throwaway code or simple automation scripts.

  • Local development with minimal complexity: Basic console.log might be sufficient for simple debugging during development.


Common Pitfalls to Watch For:

  1. Over-logging: Don't log every variable assignment or function entry. Focus on meaningful events and state changes.
  1. Inconsistent field names: Using userId in one place and user_id in another makes querying difficult. Establish and enforce naming conventions.
  1. Logging sensitive data: Never log passwords, API keys, or personal information. Always sanitize data before logging.
  1. Ignoring performance impact: Excessive logging can impact application performance. Use appropriate log levels and consider async logging for high-volume scenarios.
  1. Missing correlation IDs: Without request correlation, troubleshooting distributed systems becomes nearly impossible.

Key Takeaways

  • Structure beats volume: A few well-structured log entries are infinitely more valuable than hundreds of unstructured text logs.
  • Consistency is crucial: Establish and enforce logging standards across your entire application to enable effective querying and analysis.
  • Context is king: Always include relevant context like user IDs, request IDs, and timestamps to make logs actionable.
  • Plan for scale: Design your logging strategy to work when your application handles 10x or 100x more traffic than today.
  • Logs are data: Treat your logs as a valuable dataset that can provide insights into user behavior, system performance, and business metrics.
